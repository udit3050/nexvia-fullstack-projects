# GitHub and Render deployment

## Repository
Public repository: `udit3050/nexvia-fullstack-projects` (create before importing this folder). Keep `FS-01/` and `FS-02/` at the repository root.

## Render Blueprint
The root `render.yaml` is intended for Render Blueprint deployment. It defines the two frontends, APIs, databases and marketplace Redis, plus a dedicated Yjs WebSocket service. Review the plan and resource costs in the Render Dashboard before approving it.

## Deployment configuration
- Set the frontend API origins to the deployed API URLs.
- Set CORS `CLIENT_URL` to the corresponding deployed frontend host.
- Keep JWT secrets generated by Render; never commit `.env` files.
- FS-01 checkout is a test simulation only. It does not execute a real payment provider split or transfer.
- FS-01 product search currently uses PostgreSQL filtering; Elasticsearch is not wired in this starter.
- FS-01 image upload accepts URLs; S3 upload is not implemented.
- FS-01 invoice endpoint returns printable HTML; it is not a generated PDF yet.
- FS-02 Yjs persistence and WebSocket behavior must be verified against the deployed y-websocket server and the chosen Render plan/disk. Horizontal Redis fanout is not implemented.
